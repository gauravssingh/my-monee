# Prioritized Action List

Every finding from the four review passes, merged and sorted by severity. IDs let you cross-reference back to the detailed writeups. Checkboxes are for your own tracking — nothing here has been fixed yet.

Legend: **B** = backend/API/DB, **P** = ingestion/parsers/classification, **F** = frontend, **T** = testing/tooling, **A** = architecture/docs.

## Critical

- [ ] **B-1** — Reflected XSS in `GET /oauth/callback`: the `error` query param is interpolated unescaped into an HTML response, giving a same-origin script full read/write access to the API (read transactions, trigger sync, disconnect Gmail). `api/routes/gmail.py:132-150`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **P-1** — `GenericHeuristicParser.parse()` picks the *largest* currency amount in the email as the transaction amount, so "Avl bal: Rs.45,231.00" beats "Rs.1,250.00 was spent" — records balance instead of spend, for every YAML-only provider (HDFC, UPI/GPay). `parsers/generic.py:46`. → [03](./03-ingestion-parsers-classification.md#findings)
- [ ] **P-2** — A bare `\bsalary\b` match anywhere in an Axis email's full subject+body+HTML blob (not just the channel reference) classifies the credit as income. Marketing boilerplate mentioning "Salary Accounts" turns a ₹99 UPI transfer into "income." `parsers/axis.py:73`. → [03](./03-ingestion-parsers-classification.md#findings)
- [ ] **T-1** — `pytest` hangs indefinitely: `is_connected()` reads the real macOS Keychain instead of a test double, so on any machine with Gmail already connected, `test_sync_requires_connection` falls through into a live Gmail API call. Separately, `test_gmail_status_disconnected` currently fails outright (`assert True is False`). `ingestion/gmail/oauth.py:95-97`, `tests/test_phase2.py:24-31,86-90`. → [05](./05-testing-and-tooling.md#part-a--test-coverage-audit)

## High

- [ ] **B-2** — Path traversal in the hand-rolled SPA fallback route: `dist / full_path` is joined with no containment check, unlike `StaticFiles`. A percent-encoded `..` segment escapes `web/dist` and serves arbitrary files readable by the server process. `app.py:73-80`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **B-3** — "Current month" and the salary pay-period boundary are computed from `datetime.now(timezone.utc)`, not the user's local day. For ~5.5 hours every day (00:00–05:29 IST) the Overview reports the previous UTC day's month as current. `services/dashboard.py:16-20,98-100,156-163`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **B-4** — Every non-refund Income subcategory (Salary, Interest, Other Income) gets `transaction_type="income"` unconditionally, so the salary-only pay-period shift also silently reassigns bank-interest credits to the wrong month. `services/transactions.py:115-123` + `services/dashboard.py:59-95`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **P-3** — Discovery's `exclude_subject_patterns` filters out "transaction declined" emails before the parser ever runs, making `axis.py`'s dedicated declined-alert handling dead code in production (only reachable by calling the parser directly, as the unit test does). `config/providers/discovery.yaml:51`, `ingestion/discovery.py:67-69`. → [03](./03-ingestion-parsers-classification.md#findings)
- [ ] **P-4** — `SALARY_REF` regex is too strict for realistic narrations (`"NEFT/N123/ACME CORP/Sala"` doesn't match — no room for an employer-name segment) and breaks entirely on whitespace around slashes (`"NEFT / CHASH.../ Sala"` matches neither the salary nor the general channel pattern). Real salary credits can fall through to "needs review" as a transfer. `parsers/axis.py:21,24`. → [03](./03-ingestion-parsers-classification.md#findings)
- [ ] **F-1** — Transactions list has no pagination UI: `api.transactions()` never sends `offset`, so anything past the newest 50 (or 100 in Needs Review) rows is unreachable except by narrowing a search. `pages/TransactionsPage.tsx:44`, `api.ts:168-181`. → [04](./04-frontend.md#findings)
- [ ] **F-2** — Search/filter requests in `TransactionsPage` race with no debounce and no cancellation; a slow response for an earlier keystroke can overwrite a newer, more-specific result with stale data. `pages/TransactionsPage.tsx:37-56,220`. → [04](./04-frontend.md#findings)
- [ ] **T-2** — `ruff check src tests` is not currently a clean gate: 146 findings, and `pyproject.toml` has no `[tool.ruff.lint]` selection, so "clean" is undefined and will drift with the ruff version. → [05](./05-testing-and-tooling.md#part-a--test-coverage-audit)

## Medium

- [ ] **B-5** — CSRF-exploitable mutating endpoints (`/api/gmail/disconnect`, `/sync`, `/credentials/from-path`, `/auth/start`, `/api/transactions/sample`) take only query params, so a cross-origin `<form>` POST can trigger them with no preflight and no CSRF token. `credentials/from-path` additionally reads an arbitrary attacker-supplied local file path. `api/routes/gmail.py:99-111,171-174,177-209,114-122`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **B-6** — No database migration mechanism: `init_db` only calls `create_all()`, which never alters existing tables, and a `schema_meta.schema_version` column is written but never read. A future added column or default category silently never reaches existing installs. `db/session.py:64-83`, `db/seed.py:34-37`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **B-7** — `list_transactions` computes the pagination `total` by fully hydrating every matching row (with joins) before discarding them, then re-runs the query for the actual page — cost scales with total history, not page size. `services/transactions.py:75-98` (line 92). → [02](./02-backend-api-and-data.md#findings)
- [ ] **B-8** — Monthly aggregate queries use an inclusive `23:59:59` (no microseconds) upper bound, so a transaction at `23:59:59.5` falls into neither month's spending/category/count totals. `services/dashboard.py:16-20`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **B-9** — `domain/enums.py` exists but nothing enforces it: `direction`/`transaction_type`/`classification_source` are plain `String` columns with no `CheckConstraint`/`Enum`, and `services/dashboard.py` compares against hardcoded literals instead of the enum. A typo'd value is accepted silently and just stops matching every query. `db/models.py:134-135,154`. → [02](./02-backend-api-and-data.md#findings)
- [ ] **P-5** — Parser precedence (Axis-specific parser vs. generic YAML rule parser) is a same-score tie-break resolved only by iteration order, not an enforced priority comparison — an Axis subject variant that doesn't match the dedicated parser's keywords can silently fall through to the generic parser and inherit P-1's amount bug. `parsers/registry.py:16-26`. → [03](./03-ingestion-parsers-classification.md#findings)
- [ ] **P-6** — `config/providers/axis_alerts.yaml`'s `body_patterns` salary regex is decorative: it's used only for provider *detection*, never consulted by the actual classifier (`classify_axis_credit`), which has its own separate hardcoded pattern. Editing the YAML to fix a salary-detection bug would have zero effect. `config/providers/axis_alerts.yaml:16`. → [03](./03-ingestion-parsers-classification.md#findings)
- [ ] **P-7** — A second concurrent "Connect Gmail" click overwrites the single Keychain slot holding the first flow's PKCE `code_verifier`, silently breaking that flow with a confusing "OAuth state mismatch" error. `ingestion/gmail/oauth.py:127-134`. → [03](./03-ingestion-parsers-classification.md#findings)
- [ ] **F-3** — "Refresh status" button in Settings has no `.catch` and no busy indicator, unlike every other action on the page — a transient API failure produces an unhandled rejection with zero user feedback. `pages/SettingsPage.tsx:413`. → [04](./04-frontend.md#findings)
- [ ] **F-4** — Modals (`ClassifyPanel`, `EmailViewerModal`, `IncomeTrendModal`) have no focus trap — Tab cycles out into background page controls that remain focusable while the modal is visually open. `hooks/useModalChrome.ts:12-33`. → [04](./04-frontend.md#findings)
- [ ] **F-5** — "Sync 2026 dataset" button label and `afterDate: "2026/01/01"` are hardcoded; will read as stale and behave unexpectedly after 2026. `pages/SettingsPage.tsx:95,101,259`. → [04](./04-frontend.md#findings)
- [ ] **T-3** — `parsers/rule_parser.py`, `ingestion/gmail/mime.py`, `services/date_repair.py`, and `config.py`'s YAML-load/deep-merge path have zero test coverage. `merchants/normalize.py` has one test covering one of five real branches. → [05](./05-testing-and-tooling.md#part-a--test-coverage-audit)
- [ ] **T-4** — The entire Gmail OAuth handshake (`POST /credentials`, `/credentials/from-path`, `/auth/start`, `GET /oauth/callback`, `/disconnect`) has zero route-level test coverage — the area CLAUDE.md itself flags as most fragile. → [05](./05-testing-and-tooling.md#part-a--test-coverage-audit)
- [ ] **A-1** — `ARCHITECTURE.md` §3 documents `engine/{dedupe,refunds,transfers}.py`, `classification/{hierarchy,rules,historical,ai}.py`, `services/stats.py`, and `scheduler/jobs.py`, none of which exist; APScheduler is listed in the stack table but never installed or imported. → [01](./01-architecture-and-documentation.md)
- [ ] **A-2** — `docs/plans/MyMonee_Personal_Finance_Master_Plan.md` describes a different 12-phase roadmap under a different package name (`mymonee`) and claims a "learning-oriented classification engine" as part of the "current foundation" that doesn't exist in the code. Three documents now disagree on what phase the project is in. → [01](./01-architecture-and-documentation.md)
